# Gem5全系统仿真运行实录（基于RISC-V）

# 第四章：详解Gem5的类、继承与自定义模型

上一章中，我们分析了Gem5的基本运行机制和原理，通过外壳的方式创建了一个简易的SingleCPU。然而，我们仍然缺乏对于Gem5内部的各个类及其继承关系的认识。由于Gem5中大量使用了C++中面向对象编程的知识，如果不详细解读各个类，我们很难将其得心应手地使用。这一章节，我们详细解读Gem5的类与继承关系，并详细分析其中与CPU模型相关的核心代码，从而明白以下几个问题：

1. 如果想要通过gem5仿真框架来运行我们自己的CPU，这个CPU至少需要提供哪些内部模块或对外端口
2. 如果想要自己设计一个CPU，应该如何处理各个组件的继承关系，具体上来说代码该怎么写
3. 如果想要设计一个GPU或NPU，其与CPU会有什么不同，应该继承哪些类并提供哪些端口

## 4.1 Gem5的基本类组成

![Gem5 SimObject 类层次结构](/assets/images/gem5_riscv/gem5-simobject-class-hierarchy.png)

Gem5中包含众多的类，其中SimObject类是最基本的一个类，它是CPU、设备、内存模型等对象共同依赖的仿真框架接口。

SimObject 本身组合了五种能力，即它继承了这五个类：

```
SimObject
  ├── EventManager       事件管理
  ├── Serializable       checkpoint 序列化
  ├── Drainable          drain/排空
  ├── statistics::Group  统计信息
  └── Named              对象名称
```

因此，任何继承 SimObject 的类，都可以被 gem5 统一管理。在所有官方提供的类中，只有RequestPort和ResponsePort两个类不继承SimObject，其余类都继承了SimObject。

![Gem5 SimObject 继承关系概览](/assets/images/gem5_riscv/gem5-simobject-inheritance-overview.png)

现在我们来深入SimObject类的源码，剖析这个最基本的类，以此明白Gem5的仿真框架设计原理。SimObject的骨干代码如下：

```c++
class SimObject :
      public EventManager, // 事件管理
      public Serializable, // checkpoint 序列化
      public Drainable, // drain/排空
      public statistics::Group,  // 统计信息
      public Named // 对象名称
  {
    private:
      typedef std::vector<SimObject *> SimObjectList;

      static SimObjectList simObjectList; // 全局静态列表，保存所有已经创建的SimObject对象实例
      static SimObjectResolver *_objNameResolver; // 根据对象名称查找对象的解析器，主要用于checkpoint恢复
      ProbeManager *probeManager; // 管理该对象的probe

    protected:
      const SimObjectParams &_params; // 每个 SimObject 都保存一个参数对象的引用

    public:
      typedef SimObjectParams Params;
      const Params &params() const { return _params; } // 返回对应的参数对象引用

      SimObject(const Params &p); // 构造函数
      virtual ~SimObject(); // 析构函数

      virtual void init(); // init在所有C++ SimObject都创建完成，所有端口都连接完成之后调用
      virtual void startup(); // startup() 是仿真开始前的最后初始化阶段
      virtual void loadState(CheckpointIn &cp); // 从 checkpoint 恢复时调用
      virtual void initState(); // 在冷启动时调用，也就是没有从 checkpoint 恢复时调用
      virtual DrainState drain(); // 继承的排空函数，让对象完成当前正在处理的事务，进入一个可以暂停、切换或制作 checkpoint 的稳定状态

      virtual void regProbePoints(); // Probe系列接口，用于观察对象内部事件，是一种观察机制，不改变被观察对象的执行逻辑
      virtual void regProbeListeners();

      virtual Port &getPort(...); // 用于根据名字返回端口

      virtual void memWriteback(); // 用于把对象内部的脏数据写回内存
      virtual void memInvalidate(); // 用于使对象内部缓存或缓冲区状态失效

      virtual void serialize(...); // 继承的serializable，用于把仿真过程中对象的状态保存到 checkpoint
      virtual void unserialize(...);

      static void serializeAll(...); // 遍历所有 SimObject，为每个对象创建 checkpoint section，调用每个对象的 serialize()
      static SimObject *find(...); // 按名称查找对象
  };
```

关于这里的一些问题与解释：

1. 什么是保存所有的SimObject对象，整个Gem5仿真流程的全部SimObject子类都在这个列表中保存吗？

   是的，`simObjectList`是一个全局静态列表，它可以保存所有SimObject派生类的对象实例，实际上保存的是一个指针，在SimObject的构造函数中，这个对象的指针被加入这个列表，因此所有继承SimObject的类都会先调用这个构造函数，从而在这个列表中保存所有派生类的指针。把所有SimObject保存在这个列表的作用是统一checkpoint，按名称查找对象等，**所有SimObject实例共享同一个列表**。

2. “对象名称解析器”是什么？它有什么作用？

   它的作用是给出一个对象的名字，能够找到对应的SimObject C++指针，这个类的核心函数是输入对象的完整路径名（如system.cpu），返回一个对应对象的SimObject指针。gem5有多种配置方式，包括Python配置、C++配置、checkpoint恢复等，`simObjectList`负责统计一共有哪些对象，而`_objNameResolver`负责根据名字找到这个对象。**所有SimObject类共享一个解析器指针**。

3. 为什么在protected域定义`_params`，在下面是怎么完成对参数的使用、保存等的？

   在protected域定义`_params`，而在构造函数中会把输入的`const Params &p`绑定给`_params`，即让`_params`指向这个输入的`Params`。正常的流程中，这个Params一般由Python配置文件设置，然后gem5生成对应的C++参数对象，也可通过C++配置，但一般使用Python。使用只读引用的作用是避免复制整个参数结构，防止构造函数修改参数。从checkpoint恢复时会读取之前生成的配置重新生成对象，不会修改配置。

4. serialize是什么，有什么作用，具体是做什么？

   serialize 是 gem5 的“状态序列化”函数，用于把仿真对象当前的运行状态写入 checkpoint 文件。它保存的是运行时状态，例如对CPU来说可能保存PC、通用寄存器、控制寄存器、当前线程状态等运行时信息。它的反向操作是unserialize。默认情况下，SimObject不保存任何信息，如果需要保存，可以通过在派生类中重写这个函数来实现。

5. SimObject基类中给出的这些函数哪些是固定了实现法则的，哪些是只给出框架，需要后续派生类自己实现的？

   可以分为以下四类：

   1. 有默认实现，派生类通常可以直接使用
   2. 有默认空实现，派生类需要按需重写
   3. 有默认失败行为，派生类如果需要该功能必须重写
   4. 框架管理函数，通常不应该随意重写

   | 函数                | SimObject 默认行为                | 派生类是否经常重写       |
   | ------------------- | --------------------------------- | ------------------------ |
   | 构造函数            | 初始化基础设施、注册对象          | 必须调用基类构造函数     |
   | 析构函数            | 释放 ProbeManager                 | 有资源时重写             |
   | params()            | 返回参数                          | 通常不重写               |
   | init()              | 返回参数                          | 需要依赖完整对象图时重写 |
   | initState()         | 空实现                            | 有特殊冷启动状态时重写   |
   | loadState()         | 查找 section 并调用 unserialize() | 特殊恢复逻辑时重写       |
   | startup()           | 空实现                            | 需要安排初始事件时重写   |
   | getPort()           | 找不到端口则 fatal                | 有端口时必须提供         |
   | drain()             | 直接返回 Drained                  | 有未完成事务时重写       |
   | serialize()         | 不保存状态                        | 有运行时状态时重写       |
   | unserialize()       | 不恢复状态                        | 有运行时状态时重写       |
   | memWriteback()      | 空实现                            | 有脏缓冲时重写           |
   | memInvalidate()     | 空实现                            | 有缓存状态时重写         |
   | regProbePoints()    | 不注册 Probe                      | 需要统计观察点时重写     |
   | regProbeListeners() | 不注册监听器                      | 需要监听其他对象时重写   |
   | serializeAll()      | 统一保存所有对象                  | 通常不重写               |

   SimObject 提供的是通用生命周期框架；派生类只需要实现自己拥有的状态、端口、事件和协议。

   因此，SimObject的派生类可以按需选择这些函数进行重写，从而拓展自己的功能。这些函数定义了所有SimObject最基本的应该具有的特性以及统一的接入方式。

## 4.2 ClockedObject类的实现

ClockedObject类是 gem5 中所有“需要时钟驱动”的 SimObject 的公共基类。

它主要提供的是：

时钟域、时钟周期、仿真 tick 与本地 cycle 的转换、电压获取、功耗状态、power model 关联、checkpoint 保存与恢复。

ClockedObject继承了SimObject、Clocked这两个类，其中Clocked不是SimObject，而是一个提供时钟计算功能的辅助类。

![Gem5 ClockedObject 类层次结构](/assets/images/gem5_riscv/gem5-clockedobject-class-hierarchy.png)

代码如下：

```c++
class ClockDomain;
  class Clocked
  {
    private:
      mutable Tick tick; // 下一个时钟边沿对应的仿真 tick
      mutable Cycles cycle; // 当前 tick 对应的本地周期编号
      
      void update() const; // 将 tick 和 cycle 更新到当前仿真时间
      ClockDomain &clockDomain; // 当前对象所属的时钟域
      
    protected:
      Clocked(ClockDomain &clk_domain); // 构造函数
      
      Clocked(Clocked &) = delete; // 禁止拷贝构造
      Clocked &operator=(Clocked &) = delete; // 禁止赋值
      
      virtual ~Clocked(); // 虚析构函数
      void resetClock() const; // 根据当前全局 tick 重置本地时钟
      
      virtual void clockPeriodUpdated() // 时钟周期改变后的回调函数
      {
      }
    public:
      void updateClockPeriod(); // 更新本地时钟周期
      Tick clockEdge(Cycles cycles = Cycles(0)) const; // 获取当前或未来某个周期对应的仿真 tick
      Cycles curCycle() const; // 获取当前本地周期
      Tick nextCycle() const; // 获取下一个周期的起始 tick
      uint64_t frequency() const; // 获取当前频率
      Tick clockPeriod() const; // 获取时钟周期
      double voltage() const; // 获取当前电压
      Cycles ticksToCycles(Tick t) const; // 将 tick 转换为周期
      Tick cyclesToTicks(Cycles c) const; // 将周期转换为 tick
  };

  class ClockedObject : public SimObject, public Clocked
  {
    public:
      ClockedObject(const ClockedObjectParams &p); // 构造函数
      using Params = ClockedObjectParams; // 参数类型别名
      void serialize(CheckpointOut &cp) const override; // 保存 checkpoint
      void unserialize(const CheckpointIn &cp) override; // 恢复 checkpoint
      PowerState *powerState; // 功耗状态对象
  };

  } // namespace gem5
```

1. `mutable`是什么意思，解释一下仿真tick、仿真时间、本地周期编号、时钟域这些概念？

   `mutable`表示即使成员函数声明为const，这个成员变量依然可以被修改，比如`update()`被声明为const，但依然可以更改`tick`和`cycle`。仿真 Tick：时间的最小离散单位；仿真时间：当前模拟运行到了哪个 Tick；本地周期编号：某个组件自己的第几个时钟周期；时钟域：决定一组组件时钟频率和电压的对象。**Tick 不是 CPU 周期**，也不一定等于 1 纳秒。它的实际时间由 gem5 的全局仿真时钟决定。但是，即使 CPU 是 2 GHz，也不代表一个 CPU 周期只有 1 tick。仿真时间表示整个 gem5 仿真已经推进到的全局时间。仿真时间 ≠ 主机真实运行时间。本地周期编号表示某一个组件自己的时钟运行到了第几个周期。由于不同组件可以使用不同频率，但它们共享同一个全局仿真时间，每个组件的本地周期不同。**Clocked内部定义的tick不是全局当前时间**，而是该对象下一个时钟边沿对应的全局 Tick。时钟域维护自己的成员，当时钟频率变化时，可以通知所属对象

2. 为什么禁止拷贝构造、禁止赋值？

   这里禁止通过已有对象创建一个新的Clocked对象，禁止把一个Clocked对象赋值给另一个Clocked对象，因为Clocked域Clockdomain、tick/cycle状态、对象注册关系、事件系统密切相关，简单复制会破坏gem5的时钟和对象管理关系。

3. 什么是根据当前全局tick重置本地时钟？

   根据当前 gem5 的全局仿真时间 curTick()，重新计算某个 Clocked 对象自己的 tick 和 cycle，即根据curTick()把本地时钟对齐到第3个周期，下一个时钟边沿对应3000ticks。通常Clocked会通过update()逐步更新自己的tick、cycle，但如果全局时间或时钟状态发生特殊变化，原本的本地缓存就需要重置，重新对齐到全局时间。

4. 回调函数是什么意思？

   回调函数本身不是主动执行的，而是由其他函数在特定时机调用。它的调用时机实在更新完tick和cycle之后，让派生类知道时钟周期发生了变化，并执行额外的更新操作。

## 4.3 BaseCPU类的实现

BaseCPU类是所有CPU的基类，一般实现CPU都需要继承BaseCPU类，这个类也是SimObject的派生类，其继承于ClockedObject。其定义的代码如下：

```c++
class BaseCPU : public ClockedObject
  {
    protected:
      // 基本CPU信息
      Tick instCnt; // 保存 CPU 指令计数，主要用于一些架构相关的旧接口，不一定等价于派生CPU的totalInsts()
      int _cpuId; // CPU 的逻辑编号
      const uint32_t _socketId; // CPU 所属的物理 socket 编号，可以用于多路CPU系统、DVFS 分组、操作系统 CPU 拓扑识别、ARM MPIDR 映射

      RequestorID _instRequestorId; // 指令访存请求的 Requestor ID，CPU 取指请求发送到内存系统时，会使用这个 ID
      RequestorID _dataRequestorId; // 数据访存请求的 Requestor ID，CPU 执行 load/store 时，会使用这个 ID

      uint32_t _taskId; // gem5 内部使用的任务编号，它与操作系统 PID 不完全相同，主要用于内存系统跟踪不同任务产生的请求
      uint32_t _pid; // 当前 CPU 正在执行的操作系统进程 ID

      bool _switchedOut; // 表示该 CPU 是否已经被切出

      const Addr _cacheLineSize; // 保存系统 cache line 大小

      // 全局 CPU 统计信息，这是所有 CPU 共享的全局统计组
      struct GlobalStats : public statistics::Group
      {
          GlobalStats(statistics::Group *parent);

          statistics::Value simInsts; // 所有 CPU 总共执行的指令数，遍历仿真中的所有CPU，调用每个CPU的totalInsts()
          statistics::Value simOps; // 所有 CPU 总共执行的 operation 数量，包括 micro-op

          statistics::Formula hostInstRate; // 主机每秒模拟多少条指令
          statistics::Formula hostOpRate; //主机每秒模拟多少个 operation
      };

      static std::unique_ptr<GlobalStats> globalStats;
      SignalSinkPort<bool> modelResetPort; // CPU reset 端口，这是 CPU 的 reset 信号输入端口

    public:
      // 指令和数据端口，派生 CPU 必须实现
      virtual Port &getDataPort() = 0; // 返回 CPU 数据访存端口
      virtual Port &getInstPort() = 0; // 返回 CPU 指令访存端口
    
      //根据Python端口名称获取C++端口
      Port &getPort(
          const std::string &if_name,
          PortID idx = InvalidPortID
      ) override;
    
      //获取 CPU 标识信息
      int cpuId() const;
      uint32_t socketId() const;
      RequestorID dataRequestorId() const;
      RequestorID instRequestorId() const;

      // task ID 和进程 ID
      uint32_t taskId() const;
      void taskId(uint32_t id);
      uint32_t getPid() const;
      void setPid(uint32_t pid);
    
      // Work item 统计
      void workItemBegin();
      void workItemEnd();
      Tick instCount();
    
    protected:
      // 中断控制器
      std::vector<BaseInterrupts*> interrupts; // 保存每个线程对应的中断控制器，通常一个硬件线程对应一个中断控制器
    
    public:
      BaseInterrupts *
      getInterruptController(ThreadID tid); // 返回指定线程的中断控制器

      // 唤醒线程，派生 CPU 必须实现
      virtual void wakeup(ThreadID tid) = 0; // 可能由以下情况触发：内存请求完成、中断到达、WFI被打断、MWAIT被唤醒

      // 向指定线程发送中断
      void postInterrupt(
          ThreadID tid,
          int int_num,
          int index
      );
	  // 清除指定线程的指定中断
      void clearInterrupt(
          ThreadID tid,
          int int_num,
          int index
      );

      void clearInterrupts(ThreadID tid); // 清除该线程所有中断

      bool checkInterrupts(ThreadID tid) const; // 检查指定线程是否有待处理的中断

    protected:
      std::vector<ThreadContext *> threadContexts; // 线程上下文，保存该 CPU 的所有线程上下文
      trace::InstTracer *tracer; // 指令 tracer，指令跟踪器指针，用于记录执行的指令、PC、寄存器变化、访存信息等

    public:
      static const uint32_t invldPid; // 无效 PID
      trace::InstTracer *getTracer(); // 获取 tracer
      
      virtual void activateContext(ThreadID thread_num); // 激活某个线程
      virtual void suspendContext(ThreadID thread_num); // 挂起线程
      virtual void haltContext(ThreadID thread_num); // 停止线程，并将 CPU 周期统计状态更新为睡眠状态

      // 线程上下文管理
      int findContext(ThreadContext *tc); // 根据 ThreadContext 指针寻找对应的线程编号
      virtual ThreadContext *getContext(int tn); // 返回指定线程的 ThreadContext
      unsigned numContexts(); // 返回 ThreadContext 数量
      ThreadID contextToThread(ContextID cid); // 把系统级的 ContextID 转换为 CPU 内部的 ThreadID

    public:
      // 参数类型和构造函数
      PARAMS(BaseCPU);

      BaseCPU(
          const Params &params,
          bool is_checker = false
      );

      virtual ~BaseCPU();

      // SimObject 生命周期函数
      void init() override;

      void startup() override;

      void regStats() override;

      void regProbePoints() override;

      // 注册线程上下文
      void registerThreadContexts();

      // 功耗门控事件
      void deschedulePowerGatingEvent();

      void schedulePowerGatingEvent();

      // CPU 切换
      virtual void switchOut();

      virtual void takeOverFrom(BaseCPU *cpu);

      // CPU reset
      virtual void setReset(bool state);

      // 刷新所有 TLB
      void flushTLBs();

      // 查询 CPU 是否被切出
      bool switchedOut() const;

      // 检查内存模式
      virtual void verifyMemoryMode() const;

      // CPU 配置
      ThreadID numThreads;

      System *system;

      // Cache line 大小
      Addr cacheLineSize() const;

      // Checkpoint
      void serialize(
          CheckpointOut &cp
      ) const override;

      void unserialize(
          CheckpointIn &cp
      ) override;

      // 每个线程的 checkpoint 接口
      virtual void serializeThread(
          CheckpointOut &cp,
          ThreadID tid
      ) const;

      virtual void unserializeThread(
          CheckpointIn &cp,
          ThreadID tid
      );

      // 指令和操作数量，派生 CPU 必须实现
      virtual Counter totalInsts() const = 0;

      virtual Counter totalOps() const = 0;

      // 指令数控制
      void scheduleInstStop(
          ThreadID tid,
          Counter insts,
          std::string cause
      );

      void scheduleSimpointsInstStop(
          std::vector<Counter> inst_starts
      );

      void scheduleInstStopAnyThread(
          Counter max_insts
      );

      uint64_t getCurrentInstCount(ThreadID tid);
    public:

      // 指令提交和 PMU 探针
      virtual void probeInstCommit(
          const StaticInstPtr &inst,
          Addr pc
      );
    protected:

      probing::PMUUPtr pmuProbePoint(
          const char *name
      );
```
